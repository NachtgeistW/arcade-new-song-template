# 月度新曲表格（新曲.xlsx）填写规范

本文档描述 `months/YYYY-MM/新曲.xlsx` 的格式要求，供人工或 AI 代理（Codex 等）生成/填写表格时使用。
表格由 `scripts/prepare.ts` 读取；以下规则均与其校验逻辑一致。**生成完成后必须用 `--check` 校验通过。**

## 0. 推荐流程

1. 生成空模板（自带下拉菜单、列宽、表头注释）：
   ```
   npm run new-month -- YYYY-MM
   ```
   会创建 `months/YYYY-MM/新曲.xlsx` 和空的 `months/YYYY-MM/素材/`。文件已存在时不会覆盖。
2. 在模板上填写数据（用 `exceljs` 读入模板、写入单元格、再保存），**不要从零新建工作簿**，以免丢失下拉菜单。
3. 本地封面/音源/视频文件放进 `months/YYYY-MM/素材/`。
4. 校验（只检查表格，不下载、不处理素材）：
   ```
   npm run prepare-month -- YYYY-MM --check
   ```
   输出「表格检查通过：N 首」即合格；否则会逐条列出「第 X 行「列名」：问题」，按提示修正后重跑。

## 1. 依据的配置文件（以文件内容为准，不要凭记忆）

| 文件 | 用途 |
| --- | --- |
| `config/games.json` | 所有可填的游戏。「游戏」「参与机种」列可填 `name`、`id` 或任一 `aliases`（不区分大小写）。`"event": true` 的条目是多机种活动。 |
| `config/global.json` → `categories` | 「统计分类」列的可选值（填 `key`，不区分大小写）。 |
| `src/types.ts` → `THEMES` | 「设置」表「版式」的可选值。 |

建议「游戏」列一律填 `games.json` 的 `name` 原文（与下拉菜单一致）。

## 2. 工作表

| 工作表名 | 必需 | 说明 |
| --- | --- | --- |
| `曲目` | 是 | 本月实装的曲目，每行一首。 |
| `下月预告` | 否 | 本月公布、下月实装的曲目，显示在片尾。 |
| `设置` | 否 | 本月的版式、标题、协力名单。 |
| `_lists` | 否（隐藏） | 下拉菜单的数据源，由模板生成，不要改。 |

工作表名必须完全一致。所有单元格建议都写成**文本**（模板已把列格式设为文本 `@`）。

## 3. 「曲目」表

第 1 行是表头，从第 2 行开始是数据。按**表头文字**匹配列（列顺序可以不同，但建议保持模板顺序）。
「游戏」「曲名」「视频链接」「封面」都为空的行会被忽略（可用作空行）。

| 列名 | 必填 | 格式 / 规则 |
| --- | --- | --- |
| 序号 | 否 | 正整数，决定播放顺序。留空的行排在有序号的行之后，按表格行顺序。 |
| 分段 | 否 | 分段标题卡上的文字，多行用 `\|` 或换行分隔，例如 `jubeat\|beyond the Ave.`。留空则用该游戏在 `games.json` 的 `section`。**一般留空。** |
| 游戏 | 是 | 见第 1 节。普通机种填机种名；多机种活动填活动条目（如 `BEMANI多机种活动`、`SEGA多机种活动`）。 |
| 参与机种 | 条件 | **「游戏」是多机种活动时必填，否则必须留空。** 多个机种用 `\|` 或换行分隔，例如 `jubeat\|DanceDanceRevolution WORLD\|SOUND VOLTEX EXCEED GEAR`。每一项都必须是 `games.json` 里的普通机种（不能是活动条目），重复项会被去重。 |
| 曲名 | 是 | 照官方写法。 |
| 作曲者 | 否 | 照官方名义写法。 |
| 曲目类型 | 否 | 自由文本，显示在信息卡上，如 `本社原创` / `原创` / `VARIETY` / `版权`。 |
| 统计分类 | 否 | 必须是 `global.json` 的 `categories[].key` 之一（如 `ORIGINAL`、`VARIETY`）。留空则不计入片头统计（会有提示，但不报错）。 |
| 实装日期 | 否 | 文本 `YYYY/M/D`，例如 `2025/2/14`。也接受 `YYYY-M-D`、`YYYY.M.D`、`YYYY年M月D日` 或 Excel 日期单元格；其他写法会原样显示。 |
| 解锁方式 | 否 | 自由文本，显示在信息卡上。 |
| 视频链接 | 条件 | 见下方「素材来源」。 |
| 封面 | 条件 | 见下方「素材来源」。 |
| 音源 | 条件 | 见下方「素材来源」。 |
| 选段开始 | 否 | 文本 `分:秒` 或 `分:秒.小数`，例如 `1:23`、`1:23.5`；`时:分:秒` 也可。留空 = `0:00`。 |
| 选段结束 | 否 | 同上。留空 = 到素材结尾。必须晚于选段开始；最终选段长度必须大于 0.5 秒且不超出素材长度。 |
| 备注 | 否 | 仅自己看，不进视频。 |

### 素材来源（每行二选一，必须且只能选一种）

- **视频**：填「视频链接」，「封面」「音源」留空。
  - `http://` 或 `https://` 开头的 B 站 / YouTube 链接（由 yt-dlp 下载），或
  - `素材/` 文件夹里的本地视频文件名（如 `romancing_escape.mp4`），文件必须存在。
- **封面 + 音源**：「视频链接」留空，「封面」「音源」**两者都填**，都是 `素材/` 文件夹里存在的文件名（如 `murasaki.jpg` + `murasaki.mp3`）。

### 分段规则

- 播放时，**连续**几行的分段文字（填写值或默认值）相同时，只出一张分段卡。
- 分段卡上的 logo：
  - 这几行都是同一个普通机种 → 显示该机种 logo；
  - 这几行都是同一个多机种活动 → 轮播这些行「参与机种」的并集；
  - 混有不同游戏 → 不显示 logo。
- 因此同一游戏/活动的曲目应**排在一起**（用「序号」控制）。

## 4. 「下月预告」表

**按列位置读取**（不看表头文字）：A 列 = 游戏，B 列 = 实装日期，C 列 = 曲名，D 列 = 作曲者。第 1 行是表头。

- 「游戏」或「曲名」为空的行会被忽略。
- 「游戏」能在 `games.json` 匹配到时显示其 `name`，匹配不到时原样显示（不报错）。
- 实装日期格式同「曲目」表。
- 显示顺序：按游戏首次出现的顺序分组，组内按日期首次出现的顺序。

## 5. 「设置」表

A 列 = 项目，B 列 = 内容，C 列 = 说明（不读取）。第 1 行是表头。只改 B 列。

| 项目 | 说明 |
| --- | --- |
| 版式 | `classic` / `glass` / `stage` / `select` / `editorial` / `highway` 之一。留空使用 `global.json` 的 `theme`。填其他值会报错。 |
| 标题 | 片头大标题。留空使用 `global.json` 的 `title`。 |
| 协力 | 片尾「协力」名单，一行文本，用逗号分隔，例如 `EDTA, Rikko`。留空则不显示该栏。 |

## 7. 给代理的检查清单

- [ ] 用 `npm run new-month` 生成的模板填写，工作表名、表头文字未改动。
- [ ] 「游戏」「参与机种」的每个值都能在 `config/games.json` 找到；活动条目只出现在「游戏」列。
- [ ] 多机种活动行填了「参与机种」，普通机种行的「参与机种」为空。
- [ ] 每行只用一种素材来源；本地文件都已放进 `素材/`，文件名（含扩展名）完全一致。
- [ ] 时间、日期都写成文本（`1:23`、`2025/2/14`），没有被 Excel 自动转换成别的值。
- [ ] 「统计分类」只用 `global.json` 里的 key。
- [ ] 同一游戏/活动的曲目连续排列。
- [ ] `npm run prepare-month -- YYYY-MM --check` 通过。
